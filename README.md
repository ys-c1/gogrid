# gogrid 地形代价场与增量寻路

## 背景

旧的 `Grid.Path`（`path.go`）是单位代价 A\*，每一步固定 `+1`，只按步数寻路，
因此会径直穿过高代价地形（泥地）。本项目在此之上新增**地形权重**与**代价场**：
进入格 `(x,y)` 的代价等于该格的地形权重，寻路目标从“步数最少”变为“累计地形代价最低”。

- `.` 普通地权重 1（默认）、`g` 草地权重 2、`m` 泥地权重 5、`#` 墙体不可走。
- 权重可在运行时通过 `Grid.SetWeight` / `CostField.UpdateWeight` 修改。

## 公开 API

| API | 作用 |
|---|---|
| `NewCostField(g, source)` | 按当前权重对全图求一次完整代价场（全量 Dijkstra） |
| `CostAt(p)` | 取某格代价，不可达返回 `-1` |
| `PathTo(to)` | 返回到目标的最低代价路径（含起终点）与总代价 |
| `UpdateWeight(p, w)` | 改单格权重并**增量**刷新，返回 `UpdateStats` |
| `UpdateOrRecompute(p, w)` | 同上；越界时自动回退一次全量重算 |
| `Recompute()` / `FullRecompute()` | 强制全量重算，返回重算格数 |
| `Equals(other)` | 逐格比较两个代价场的代价与前驱（增量 vs 全量对照） |
| `Grid.Clone()` | 深拷贝网格（含墙体与权重），供对照实验 |

`UpdateStats` 字段：

```go
type UpdateStats struct {
    Changed    Point   // 变更格
    OldWeight, NewWeight int
    Recomputed int     // 实际重新赋距的格数（核心上报指标）
    Boundary   []Point // 边界格：受影响区域外缘、距离不变、作为增量 Dijkstra 的种子
    Affected   []Point // 受影响区域内被重算的格
    FellBack   bool    // 是否回退到了全量重算
}
```

## 算法

### 1. 全量代价场

从源点跑 Dijkstra，边 `u -> v` 的松弛代价为 `dist[u] + weight[v]`（权重在“进入”目标格时结算，
源点自身代价恒为 0）。`dist` 存全图每格的最小累计代价，`parent` 存最短路径前驱，
`PathTo` 沿前驱回溯即可还原路径。

### 2. 增量更新（只重算受影响区域）

设变更格为 `p`。

**权重上升 `newWeight > oldWeight`：**

1. 沿 `parent` 边反向传播，标记所有“最短路径经过 `p`”的格，构成受影响区域。
2. 区域外缘、自身不在区域内的可达格即**边界格**——它们的距离不受影响，作为种子。
3. 清空区域内各格的距离/前驱，把边界格（区域含源点时再加上距离为 0 的源点）放入堆，
   跑一次**只在区域内部松弛**的有界 Dijkstra。

**权重下降 `newWeight < oldWeight`：**

1. 先在 `p` 的所有邻居中重算 `p` 自身的最优距离与前驱（必须在它入堆之前完成，
   否则会以旧距离先出堆、提前锁死前驱——这是实现过程中实测到的一个真实缺陷）。
2. 以 `p` 为唯一种子做有界 Dijkstra，仅当某格真正变短（或等代价但前驱更优）时才重赋距并计数。
3. 被重算格的外缘邻居作为边界格单独列出。

### 3. 边界格（单独列出）

`stats.Boundary` 是受影响区域与未受影响世界之间的“接缝”：

- 它们的距离在本次变更中**保持不变**；
- 上升场景里它们直接充当有界 Dijkstra 的初始种子；
- 测试 `TestIncrementalMatchesFull` 会逐个断言：边界格不在受影响区域内、
  与至少一个受影响格相邻、且增量与全量代价一致。

### 4. 回退到全量重算

`UpdateWeight` 在两种情况下不做增量、直接全量：

- **变更格当前不可达**（与源点不连通的孤岛）：它不参与任何源点最短路径，
  单格权重变更不会改变任何可达格代价，因此只落权重、零重算。
- 受影响区域既没有边界种子、又不含源点（理论上不会发生，作为防御性兜底）：
  置 `FellBack=true` 并调用 `Recompute()`。

`UpdateOrRecompute` 额外处理**坐标越界**：调用方无法保证变更位置在界内时，
越界返回带坐标的 `ErrOOB`，同时回退一次全量重算并在错误信息中注明“已回退全量重算”。
负权重、墙体等非法输入仍然原样报错，**不**触发回退。

### 5. 关键正确性不变量

- 权重只在可走格上变更且始终为有限非负值，**墙体与四邻域连通性不变**，
  因此可达格集合在代价场生命周期内恒定；不可达格永远不会与可达格四邻接。
  这保证了增量标记不会把孤岛误吸进受影响区域（早期版本曾因洪水扩散污染孤岛而产生错误可达性）。
- 全量与增量三处 Dijkstra 使用**同一套确定性 tie-break**：等代价时选一维下标更小的前驱。
  否则同距离的多条最短路径会因发现顺序不同而选到不同前驱，导致逐格比对失败。
- `fullDijkstra` 用 `settled` 标记保证每格只在首次定距时计数一次，
  `Recomputed` 因而等于实际定距的可走格数（重复/过期堆条目不会虚增计数）。

## 错误处理（均带坐标，可用 `errors.Is` 分类）

| 情形 | 哨兵 | 示例信息 |
|---|---|---|
| 权重为负 | `ErrNegativeWeight` | `权重为负: 坐标(0,0) 权重=-1` |
| 网格为空 | `ErrEmpty` | `网格为空` / `网格为空: 无法建立代价场` |
| 终点/源点不可走（墙体） | `ErrBlocked` | `格点不可走: 终点坐标(1,0) 不可走` |
| 坐标越界 | `ErrOOB` | `坐标越界: 坐标(9,9)` |
| 终点不可达 | `ErrNoPath` | `无可行路径: 终点坐标(2,0) 不可达` |

## 等权路径行为不变

当全部可走格权重为 1 时，地形代价退化为路径边数，代价场路径与旧单位代价 A\* 完全一致。
`TestEqualWeightUnchanged` 断言两条路径逐格相同、代价等于路径边数。

## 增量与全量对照

- `TestIncrementalMatchesFull`：上升、下降、泥地降草地等 5 组用例，每次都用 `Grid.Clone()`
  建一份独立参考场做全量重算，`Equals` 逐格比对代价与前驱，并断言增量重算格数不超过全量。
- `TestRandomIncrementalConsistency`：200 个随机网格（随机墙体与泥/草/普通地形），
  每个连续 5 次随机权重变更，每次都与全量重算逐格核对。
- 演示程序 `go run ./cmd/costdemo` 在泥地、草地、混合、无路、同点等场景实时打印
  “增量 vs 全量 ✓ 逐格相同”、两侧重算格数、耗时与边界格。

## 两档网格基准（`go test -bench`）

环境：13th Gen Intel i7-13620H，linux/amd64。增量用例在泥地边缘格上改权重。

| 网格 | 全图可走格 | 全量重算耗时 | 增量更新耗时 | 增量重算格数 |
|---|---|---|---|---|
| 20×20 | 381 | ~36 µs | ~2 µs（约 17×） | 2 |
| 100×100 | 9901 | ~1.5 ms | ~25 µs（约 55×） | 9 |

全量代价随总格数线性增长；增量代价只与受影响区域大小相关，
局部权重变更时基本与全图规模解耦。复现：

```bash
go test ./grid/ -run='^$' -bench='Benchmark(Full|Incremental)' -benchmem
go test ./... -race -count=1
go run ./cmd/costdemo
```
